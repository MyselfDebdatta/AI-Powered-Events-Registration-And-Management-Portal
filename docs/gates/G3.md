## 3. Migration evidence — three paths

All paths were run against a disposable `pgvector/pgvector:pg16` container.

| Path | Command | Result |
|---|---|---|
| Fresh upgrade | `alembic upgrade head` on an empty database | 8 revisions applied; head `010_constraints_indexes` |
| Upgrade from populated `002` | `alembic downgrade 002_security_foundation`, insert synthetic rows, `alembic upgrade head` | All 5 pre-existing rows preserved; backfills correct; `marked_at` unchanged |
| Full downgrade | `alembic downgrade base` then `alembic upgrade head` | Clean; each `downgrade()` dropped only what its revision added |

Observed on the populated path:

- event: `code=oas-2026`, `name='Odisha AI Symposium 2026'`, `starts_at=NULL`, `venue=NULL` — no invented facts.
- participant with an existing embedding: `status=SYNCED`, `source=ADMIN`, `event_id=1`.
- embedding: `model_name=insightface`, `model_version=unknown-not-installed` (explicit placeholder — InsightFace is not installed in CI/dev), `dimension=512`, `is_active=true`.
- attendance: `client_event_id=00000000-0000-0000-0000-000000000001`, `is_void=false`, `marked_at=2026-11-20 10:00:00+00` (unchanged).

A defect found by the populated drill (a malformed UUID literal in M6 that only manifests with real rows) was corrected before this evidence was recorded.

**M9 verification:** a fresh database at head has no default login. `POST /api/auth/login` with any credentials before bootstrap returns 401; bootstrap is the only first-admin path (verified by the S1 regression suite).
